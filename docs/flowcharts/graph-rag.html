知识图谱 RAG（Graph RAG）
大狗嚼电竞 · backend/rag/graph_retriever.py · backend/kg/ · Neo4j —— 多路召回里的第三路
为什么单独开一路：向量检索擅长语义相似，但对「这个老板找过哪几个打手」这类 关系型问题很吃力 —— 答案不在任何一段文字里，而在实体之间的边上。关键词检索更不行， BM25 只看词频，算不出多跳关系。

B · 查询侧 —— 提问时这七步
入口 GraphRetriever.retrieve(question, role, username, limit)
①可用性三关kg.store.is_ready()
驱动装了没（neo4j 包）→ 密码配了没（NEO4J_PASSWORD 在 backend/.env）→ 连得上没。任一不过直接返回空列表。
②实体链接_link_entities()
让 Neo4j 去判断「问题文本里是否包含某个节点的标识」，可匹配五类： 账户名 昵称 订单号 游戏名 标签名
账户名、订单号属于精确标识符，命中给强加成；昵称、游戏名、标签只是字面包含，可能碰巧撞上，只给弱加成。这个判定会一路带到重排序阶段。
③本人兜底
老板和打手问「我的订单」时，问题里根本不会出现自己的账户名，实体链接必然一无所获。此时若角色是 boss / player 且没匹配到任何实体，直接把「本人节点」当作默认命中 —— 这样「我的订单」也能走图谱。
④权限过滤_visible()
与 kg/api.py 的可见性规则保持一致：
管理员 / 客服 —— 看全量节点
老板 / 打手 —— 只能看自己（按传入的 username 收敛）
⑤取一跳邻域_collect_facts(seeds, limit)
把这批实体的邻居和关系一次性捞出来，条数由系统参数 rag_graph_limit 控制（默认 3）。
⑥渲染成人话_render() / _render_props() / _fmt()
输出形如「老板 laoban —下单→ 订单 ORD2026…」的主谓宾事实。
字段中文名映射
如 backend_amount → 后台金额、player_username → 打手、boss_username → 老板。
created_at 统一翻译为中性词「时间」—— 因为它在各表里含义不同（下单 / 评价 / 打赏 / 提现），否则会把打赏时间渲染成「下单时间」。
敏感字段抹除
余额 · 累计消费 · 后台金额 · 订单金额 · 金额 · 打赏金额
对非管理员一律抹掉，只在管理员视角显示。
⑦包装并并入融合Document(source_type="graph")
每条事实包装成一个 Document，带 node_id / label / key / node_name / match_field / match_score 元数据， 进入加权 RRF 融合，通道权重 1.3（三路中最高）。
事实只带渲染后的文本，不带原始属性字典 —— 因此不会绕过第 ④ 步的权限过滤。
C · 一跳邻域长什么样（以一条订单为中心）
示意结构，用于说明关系型问题为什么必须靠图
老板 laoban —下单 PLACED→ 订单 ORD2026… —承接 SERVED→ 打手 dashou_09
↳ 游戏 无畏契约 评价 5 星 打赏 8.00 元
问「laoban 找过哪些打手」→ 从老板节点走一跳就能拿到全部订单与承接人； 这在向量库里没有任何一段文字能直接回答。
D · 失败降级 —— 这条通道绝不能拖垮问答
驱动没装
提示「pip install neo4j」，图谱功能关闭
密码没配
提示看 backend/.env 的 NEO4J_PASSWORD
连不上 Neo4j
本次跳过，只打印一行日志
Cypher 报错
返回空列表，绝不抛异常
RAG 少了这一路照样能答，只是答不了关系型问题。所有异常都被吞掉并降级为空召回。

F · 在整体 RAG 中的位置
查询增强产出的 N 个变体 → 关键词通道（每变体） 向量通道（每变体） ✚ 图谱通道（仅原始问题一次） → 加权 RRF 融合（图谱权重 1.3） → 重排序 → Self-RAG 过滤 → 上下文构建 → 生成
图谱通道不跟着查询变体分裂，是因为实体链接依赖问题里的字面标识（账户名、订单号、游戏名）； 改写出来的变体（同义扩展、HyDE、子查询拆分）往往已经不含这些标识，拿去匹配只会白跑几趟 Neo4j。
